What Is Image Compression? Lossy vs Lossless Explained

Lossy or lossless? The distinction sounds technical, but it determines whether a compression tool destroys your detail or keeps it. This article explains both approaches in plain language, compares them side by side, and gives you a rule of thumb for when each one is the right choice.

What Compression Actually Does

A digital image is a grid of pixels, each carrying its own colour value. That grid is the complete description of the picture. The "size" of the file is simply the amount of data required to describe every pixel. If you have a 1000 × 1000 photograph, you have roughly one million pixels, and each one needs somewhere between a few bytes and a few dozen bytes of information. That is the uncompressed reality of an image file, and it is what "raw" means in photography: a file that describes every pixel without any attempt to save space.

Compression is the art of describing the same picture with less data. You do this by finding patterns, smoothing areas that change gradually, and discarding information that is unlikely to be noticed. The question is what kind of information you are allowed to discard. That is where lossy and lossless split.

Lossless Compression: The Exact Copy

Lossless compression reduces file size without changing a single pixel. Every colour value that goes into the compressor comes out of the decompressor exactly the same. The original file is preserved at a fixed, mathematically guaranteed size. You can apply lossless compression as many times as you like, and the pixel data will always remain identical.

The analogy that helps most is a zip file. A zip file does not change the contents of the files inside; it merely stores them in a more compact way. PNG and WebP in lossless mode work the same way: they find redundancy in the pixel data and store it more efficiently. If you open a lossless PNG and a lossless WebP of the same image, you will see the same colours and shapes, just stored with different amounts of efficiency.

Lossless compression runs up against a hard ceiling. A photograph with smooth gradients and millions of subtle colour variations does not contain much redundancy, so there is only so much you can compress it. A high-resolution photograph is likely to compress to a PNG that is three to five times larger than the same photo in a lossy format. This is a limitation of the image content, not the tool.

Lossy Compression: The Deliberate Trade-Off

Lossy compression deliberately discards information in order to achieve a much larger reduction in file size. JPEG is the most familiar example. The encoder identifies the details that matter least to the human visual system and removes them. The result is a smaller file that still looks like the original when viewed at a normal distance.

The cost, of course, is that the discarded data is gone forever. This is not a reversible process. A JPEG that has been saved and re-saved repeatedly will accumulate more loss each time, and you will eventually see blocks, fringing, and a sandy texture. This is why professional photographers never re-save a JPEG; they keep an archive copy in a lossless or raw format and only ever save a working JPEG once.

The amount of loss is controlled by the quality setting. A quality setting of 95 or 100 on a JPEG produces a barely perceptible reduction in size. Drop the quality to 70–80, and you will save a great deal of space with a difference that is very hard to see on screen. This is the trade-off in action: in a double-digit percentage point reduction of file size, you lose so little that the viewer will never notice.

When to Choose Which

The decision comes down to three practical questions.

  • Do you need the original preserved forever? Use a lossless format. If you are archiving a rare set of photographs, the archive should be lossless (or raw) so that no information is ever lost.
  • Do you need the image to stay sharp and clean? Use a lossless format. Text, line art, logos, and illustrations benefit from lossless compression because lossy compression softens edges and creates visible artefacts around fine detail.
  • Do you need the smallest possible file for the web? Use a high-quality lossy format. A JPEG or WebP at quality 80–85 is the standard for photographs on the web, because the visual difference is negligible and the file size savings are substantial.

The JPEG Ringing Effect: A Concrete Example

The clearest demonstration of lossy compression is what happens to a small, high-contrast detail. Take a sharp black line on a white background. A lossless file preserves that black line exactly. A JPEG at 95% quality will still show a clean black line. At 60% quality, the edges of the line will begin to flicker slightly: a few light pixels will appear inside the black line, and a few dark pixels will appear in the white background. These are the pixels that the encoder decided were not "important enough" to keep. The line is still visible, but it is no longer perfectly clean.

Practical Examples from Real Projects

A photographer needs to keep the original raw file, and a separate JPEG for web use. The raw archive is lossless and preserves every detail; the web JPEG is highly compressed but is created from the original, never re-saved, so the accumulated damage never happens. A website designer receives PNG screenshots from a developer with text and transparency. They convert to WebP for the site, which preserves the text and transparency while shrinking the file size. A newsletter designer receives a photograph with a transparent background. They convert the PNG to JPG and fill the transparent areas with white, because the email client cannot handle transparency. Each of these decisions is an instance of a simple rule: pick the format that preserves the structure that matters, and compress for the environment that matters.

Summary

Lossless and lossy are not competing values; they are different tools for different jobs. Use lossless when the information must be preserved exactly: archives, graphics with text, transparency. Use lossy when the file has to be small and the detail is less important: photographs for the web.
